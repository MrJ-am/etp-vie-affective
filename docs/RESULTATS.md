# Vérifications exécutées le 6 octobre 2026

Cette livraison vérifie l’interface en classeur : six feuilles distinctes, douze capsules de chapitre sur la feuille du parcours et trois bilans conservés. Les résultats bruts de la version finale sont dans `browser-results.json`, `site-classeur-results.json` et `integrite-classeur.json`. Les preuves précédentes restent dans `unit-results.txt`, `api-results.txt`, `storage-results.txt`, `restore-results.txt`, `photo-metadata-results.txt` et `historique/`. Tous les comptes, notes et photos d’essai sont inventés ; aucun participant, patient ou secret réel n’est enregistré dans ces artefacts.

**63 cas navigateur ont passé dans une exécution complète, sans échec, cas ignoré ou retry : 21 sur chacun des trois moteurs.** Les 13 unités et 9 cas API réels ont passé lors de la refonte précédente du même jour ; ils n’ont pas été relancés pour cette modification de présentation. Leurs fichiers métier, crypto et backend sont identiques par SHA-256. Les exercices de restauration, inspection du stockage et EXIF proviennent de la livraison initiale du même jour, sur ces mêmes contrats. Voir `verification-final.json`.

Les tests navigateur passent par un relais localhost qui transmet les vraies requêtes au serveur Lisp/PostgreSQL isolé, sans mocks d’API. Aucun retry automatique n’est configuré. Le contrôle du déploiement allonge seulement les transitions natives de capsule dans le test, puis observe la hauteur du corps et la position de sa voisine pendant le mouvement ; aucun état d’application ou mouvement n’est simulé. Les durées livrées restent 320 ms pour une feuille, 520 ms pour une capsule, 380 ms pour un moment et 320 ms pour le paysage.

Une première exécution a été interrompue après un échec du contrôle de trace : l’attente pouvait lire l’ancien état « Chiffré » avant le traitement du clic de création, puis recharger trop tôt. Le contrôle attend maintenant la confirmation de création avant la fin du chiffrement ; le flux de sauvegarde n’a pas changé. Une autre exécution a été interrompue pour corriger un indicateur de mouvement restant actif lorsqu’une fermeture était annulée avant son départ. Le contrôle ciblé a ensuite passé sur les trois moteurs, puis a été inclus dans la régression complète. Les rapports intermédiaires sont identifiés comme tels dans `historique/` ; ils ne sont pas additionnés au nombre de cas finaux. Les rapports de l’ancienne interface continue y sont conservés séparément.

L’artefact statique destiné à la publication privée est ouvert réellement sur localhost : démo uniquement, six onglets, une feuille accessible, douze capsules et trois bilans, retour au même moment par onglet et par bouton, et lien du code complet vérifiés ; aucune requête `/api/` et aucune erreur JavaScript dans ce mode. `site-classeur-results.json` décrit ce contrôle de l’artefact local. Le statut natif de publication fournit séparément la vérification de l’URL. La version complète locale sur http://localhost:3000 sert les vrais comptes et le backend ; ce loopback distant n’est pas une URL publique accessible depuis l’ordinateur du destinataire.

Les comparaisons de `integrite-classeur.json` portent sur neuf fichiers : catalogue, modèle privé, décodeur de contenu, crypto, Worker, serveur Lisp, image backend, migration SQL et révision du thème partagé. Les seules modifications du pont TypeScript concernent le focus et la position de lecture sous les onglets ; aucun flux de chiffrement, réseau ou stockage n’est modifié.

Le contrôle EXIF initial sur le vrai serveur local a inséré un segment EXIF valide et un marqueur fictif dans un JPEG généré. Après ajout via l’interface et déchiffrement de l’export, le JPEG nettoyé ne contient ni EXIF ni marqueur. La fixture de compte a été supprimée ; résultat dans `photo-metadata-results.txt`.

## Limites des essais

Les largeurs, le paysage et les changements de taille sont des émulations navigateur, pas des essais sur smartphone ou écran pliable physique. Le clavier virtuel mobile, VoiceOver/TalkBack/NVDA avec une personne, le zoom natif sur plusieurs OS, la restitution des alertes par lecteur d’écran et les préférences d’adultes autistes n’ont pas été évalués humainement. La compréhension de la métaphore du classeur reste aussi à évaluer avec les personnes destinataires. Aucun persona simulé ne remplace ce travail. Les scans axe ciblés ne certifient pas la totalité WCAG 2.2 AA.

La CI est écrite mais n’a pas été exécutée sur GitHub Actions distant. Les commandes ont été exécutées localement. L’exemple NixOS/Nginx/systemd n’a pas été déployé ou évalué sur un VPS. Pas de test d’intrusion indépendant, audit cryptographique, certification HDS ou validation clinique. PBKDF2 doit être mesuré sur appareils mobiles réels ; les futures migrations et rotations de clé doivent être conçues avant introduction d’un nouveau format.

L’export et la suppression des copies sur d’autres appareils restent à charge de leurs détenteurs. Le rejeu du journal ne protège une restauration que si le journal **actuel** est conservé séparément ; l’exercice réalisé vérifie ce contrat précis. Les métadonnées temporelles et volumes subsistent. Un opérateur actif contrôlant le code livré demeure une menace explicitement ouverte.
