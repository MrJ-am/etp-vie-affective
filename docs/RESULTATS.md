# Vérifications exécutées le 6 octobre 2026

Les résultats bruts sont joints : `unit-results.txt`, `api-results.txt`, `browser-regression-results.json`, `browser-continuite-results.json`, `storage-results.txt`, `restore-results.txt`, `photo-metadata-results.txt`, `site-continuite-results.json` et `integrite-continuite.json`. Tous les comptes, notes et photos d’essai sont inventés. Les captures montrent le carnet fictif ; aucun participant, patient ou secret de récupération n’est enregistré dans ces artefacts.

**85 tests distincts validés, aucun ignoré : 13 unités, 9 cas API réels et 63 cas navigateur (21 par moteur).** Ces suites ont été exécutées après la refonte continue. Les exercices de restauration, inspection du stockage et EXIF ont été exécutés lors de la livraison initiale du même jour ; leurs résultats restent joints. Les fichiers métier, de chiffrement et du backend sont identiques à ceux de cette livraison. Voir aussi `verification-final.json`.

Les tests navigateur passent par un relais localhost qui transmet les vraies requêtes au serveur de test, sans mocks d’API. Aucun retry automatique n’est configuré. Le contrôle d’interruption allonge uniquement la durée native dans le test pour observer un déplacement réel, puis compare le point de départ de la transition inverse. Il lit la propriété CSS calculée, car WebKit peut conserver une mesure géométrique ancienne pendant une transition. Les durées de l’interface livrée sont 460, 380 et 320 ms. La régression complète conserve un échec du premier protocole de mesure sur WebKit : le panneau continue d’avancer entre le clic et les images qui préparent la navigation. Les 60 autres cas passent sur les trois moteurs. Le contrôle corrigé utilise l’instant natif de `transitioncancel` et vérifie le départ inverse à moins de deux pixels ; il a ensuite passé séparément sur les trois moteurs. Aucun code d’interface n’a changé entre ces exécutions. `browser-results.json` est un index explicite des 63 cas distincts validés et de leurs preuves, pas un rapport Playwright brut. Les deux rapports bruts restent joints ; aucun retry automatique n’a été utilisé.

L’artefact destiné à la publication privée a aussi été ouvert réellement sur localhost : entrée en mode démo uniquement, plan de six espaces, quinze étapes, retour au même moment de séance et lien du code vérifiés ; aucune requête `/api/` dans ce mode. Le statut natif de publication fournit séparément la vérification de l’URL. L’interface complète, y compris le paysage, a aussi été ouverte pour actualiser les captures. La version complète locale est servie réellement sur http://localhost:3000 dans cet environnement ; ce loopback distant n’est pas une URL publique accessible depuis l’ordinateur du destinataire.

Un contrôle complémentaire sur le vrai serveur local a inséré un segment EXIF valide et un marqueur fictif dans un JPEG généré. Après ajout via l’interface et déchiffrement de l’export, le JPEG nettoyé ne contient ni EXIF ni marqueur. La fixture de compte a été supprimée ; le résultat figure dans `photo-metadata-results.txt`.

## Limites des essais

Les largeurs, le paysage et le changement de taille sont des émulations navigateur, pas des essais sur smartphone ou écran pliable physique. Le clavier virtuel mobile, VoiceOver/TalkBack/NVDA avec une personne, le zoom natif sur plusieurs OS, la restitution des alertes par lecteur d’écran et les préférences d’adultes autistes n’ont pas été évalués humainement. Aucun persona simulé ne remplace ce travail. Les scans axe ciblés ne certifient pas la totalité WCAG 2.2 AA.

La CI est écrite mais n’a pas été exécutée sur GitHub Actions distant. Les commandes ont été exécutées localement. L’exemple NixOS/Nginx/systemd n’a pas été déployé ou évalué sur un VPS. Pas de test d’intrusion indépendant, audit cryptographique, certification HDS ou validation clinique. PBKDF2 doit être mesuré sur appareils mobiles réels ; les futures migrations et rotations de clé doivent être conçues avant introduction d’un nouveau format.

L’export et la suppression des copies sur d’autres appareils restent à charge de leurs détenteurs. Le rejeu du journal ne protège une restauration que si le journal **actuel** est conservé séparément ; l’exercice réalisé vérifie ce contrat précis. Les métadonnées temporelles et volumes subsistent. Un opérateur actif contrôlant le code livré demeure une menace explicitement ouverte.
